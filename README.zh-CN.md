# 单品牌深度数据看台

[English](README.md) | [简体中文](README.zh-CN.md)

> 为单一品牌、单店或单个 IP 做「全维度数据画像看台」，一份数据同时产出三种交付物。

## 这是什么

这不是一个区域横向盘点。同门的 `local-wanghong-audit` 回答的是"这个区域里有哪些店"，这一个回答的是一句更窄也更难的问题：这一个东西到底是怎么回事。

动手的第一步是可行性尽调，不是采数据。人们开口要的那些数字 —— 全网数据量、年度指数曲线、好评差评的准确条数 —— 相当一部分在产品层面根本不对外。花五分钟先查清楚，比先产出一份看似笃定、其实全建立在没人认可的替代指标上的报告要划算得多。

## 为什么开源

同一段对话反复出现：有人要一份品牌数据画像，而诚实的回答必须先讲清楚哪些量不出来，才能讲能量什么。

所以我们把流程写下来了，包括讲边界那一段。它之所以适合分享，恰恰是因为它通用 —— 各平台到底开放什么，这份清单跟谁做调研无关，而且里面不含我们自己的任何分析结论。

## 能做什么

- **先做可行性尽调。** 在承诺任何指标之前，先过一遍各平台通过接口到底开放了什么，结论写下来。
- **诚实地替换指标。** 数字拿不到的时候，替代指标是明确挑选的，替换这件事本身也在交付物里写明。
- **可复现的关键词词频。** 专门写的中文 n-gram 实现，词频可以重新算一遍，不用凭信。
- **一源三渲。** HTML 看台、Word 报告、Excel 台账从同一份数据出来，不会出现几种格式之间互相矛盾。
- **结论带来源。** 每个判断都挂着证据，没有依据的说法会标出来。

## 怎么用

说清对象和你想知道什么：

- "给某某做一个数据看台"
- "某某这家店全网声量多大，大家怎么说"
- "某某为什么火，现在还热吗"

它会从"能拿到什么、拿不到什么"开始。这一步是重点本身，不是障碍。

## 注意与边界

1. **接口上限就是上限，跟方法聪不聪明无关。** 一个数字接口不开放，再怎么绕也拿不到。仓库里这一点写得很直白。
2. **词频是描述，不是解释。** 词频说明出现了什么；它意味着什么，仍然是人的判断。
3. **小样本会把比例拉歪。** 被提到三十次的品牌和三十万次的，不该放在同一个刻度上比。
4. **评价条数通常拿不到全量。** 平台给的是一个展示用的数字，不是一份能取下来的数据集。
